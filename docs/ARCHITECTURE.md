# 📊 TradingView Signal Bot - SaaS 平台架构

## 🎯 项目概览

这是一个从单机版交易信号机器人升级而来的 SaaS 平台，支持多用户、多任务、多指标的交易信号监控系统。

### 表关系说明

1. **User → Task**: 一对多（用户创建的任务）
2. **Market → Task**: 一对多（一个标的可有多个任务）
3. **Task ↔ Indicator**: 多对多（通过 TaskIndicator）
4. **Task → TaskExecution**: 一对多（任务执行历史）
5. **TaskExecution → IndicatorResult**: 一对多（每次执行的指标结果）

## 🔄 数据流

### 任务创建流程

```
用户 → 前端表单 → API 验证 → Prisma ORM → PostgreSQL
                                    ↓
                            任务调度器注册
```

### 信号监控流程 (实时模式)

```
任务调度器启动
     ↓
TradingViewService 创建 WebSocket 连接
     ↓
订阅市场数据和指标
     ↓
实时接收指标更新 → SignalManager 去重检查
     ↓                      ↓
   有信号?               无信号 → 继续监听
     ↓ Yes
存储到 TaskExecution + IndicatorResult
     ↓
NotificationService 发送通知
     ↓
更新 SignalStatistics
```

### 信号扫描流程 (定时模式)

```
Cron 调度器触发
     ↓
TradingViewService 读取指标数据
     ↓
遍历所有标的 → 检查信号
     ↓                ↓
   有信号?         无信号 → 下一个标的
     ↓ Yes
存储结果 → 发送通知 → 更新统计
     ↓
等待下次执行时间
```

## 🔐 安全机制

### 认证与授权

```
请求 → NextAuth 中间件 → Session 验证 → 角色检查 → API 处理
                              ↓ 失败
                         返回 401/403
```

### 数据验证

```
前端输入 → React Hook Form + Zod → API 接收 → Zod 再次验证
                                                  ↓
                                            Prisma 类型安全
```

### 审计日志

所有重要操作都记录到 `CommonLog` 表：
- 创建/更新/删除 标的
- 创建/更新/删除 指标
- 创建/更新/删除 任务
- 用户登录记录 (UserLoginIp)

## 📊 性能优化

### 数据库优化

1. **索引设计**
   - 所有外键添加索引
   - 常用查询字段添加索引
   - 联合索引优化多条件查询

2. **查询优化**
   - 使用 Prisma 的 `include` 和 `select` 精确加载
   - 分页查询避免大数据量
   - 使用 `relationJoins` 特性优化关联查询

3. **连接池**
   - Prisma 自动管理连接池
   - 生产环境配置合适的连接数

### 前端优化

1. **React Query**
   - 智能缓存
   - 自动重试
   - 乐观更新

2. **代码分割**
   - Next.js 自动代码分割
   - 动态导入重组件

3. **SSR/SSG**
   - 静态页面生成
   - 服务端渲染
